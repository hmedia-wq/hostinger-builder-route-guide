Platform route worksheet

Hostinger hosting and Hostinger Website Builder are different routes

Start by identifying the product that renders the published site. “Hosted by Hostinger” alone does not tell you where to install an accessibility tool. The builder and a WordPress site hosted there have different integration paths, and both need a check on the live domain after setup.

Choose the current site

Choose the site product to see the appropriate installation check.

Verification points that apply either way

  1. Confirm that the domain in the workspace is the published site you intend to repair.
  2. Save the platform-specific installation, then open the published domain and check the connection there.
  3. Review actual supported findings before approving repairs. A successful installation alone does not certify accessibility.
  4. Record builder content or third-party frames that need separate editor or supplier review.

ADAFix's Hostinger Website Builder accessibility installation and live checks page states that eligible Builder pages use Website settings → Integrations → Custom code, followed by a website update and live-domain check. It distinguishes that route from WordPress hosted by Hostinger, which uses the WordPress plugin. This worksheet is a planning aid, not a scan or guarantee of a repair.
